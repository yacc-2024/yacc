# yacc

YACC 创作组的手机版作品集 App —— 反对校园霸凌公益短片项目。

纯前端 PWA，数据保存在本设备，零服务器、零月费。

---

## 快速开始

```bash
# 需要 Node.js 18+（本地 API 需要 22+，因为用了内置 sqlite）
pnpm install
pnpm dev:online     # 前端 5173 + 本地 API 8788，一起起
# 或只跑前端（离线模式）
pnpm dev
```

手机同一 WiFi 下用终端打印的 192.168.x.x 地址打开即可。

> 在线功能（账号、评论、点赞、云端发布）见 **[DEPLOY-ONLINE.md](DEPLOY-ONLINE.md)**。
> 没有后端时，App 会自动退回离线模式（内容读 `content.json`，账号存本机）。

### 第一次当管理员

打开后 → 我的 → 登录页底部「我是负责人」→ 输入**激活码**。

- 开发默认激活码：`YACC-ADMIN-2026`
- 改法：复制 `.env.example` 为 `.env.local`，把 `VITE_ADMIN_CODE` 换成你自己的
- 线上部署：在托管平台的环境变量里设置同名变量，否则会用默认值

> 安全说明：静态站点里的常量都能被看到。激活码挡的是"随手点两下就成了管理员"，
> 真正的边界是"能不能改仓库、能不能发布"。真正的在线权限见 [V2-在线化方案备份.md](V2-在线化方案备份.md)。

普通成员用**邀请码**注册（默认 `YACC2026`，在管理中心改），不需要激活码。

## 内容怎么改

**不需要碰代码。** 所有内容都在「我的 → 管理中心」里改：

| 入口 | 能改什么 |
| --- | --- |
| 主页管理 | 头图主张、简介、统计、三组数据、最新推荐、公告、活动 |
| 关于页管理 | 引言、数据来源、项目历程 |
| 成员管理 | 成员增删改、分工、参与季、排序 |
| 作品管理 | 季、剧集、花絮，粘贴 B 站链接自动识别 |
| 数据管理 | 在线时「发布到线上」；导出、导入、撤销上次导入、清除草稿 |
| 密钥管理（在线） | 生成认证访客 / 访客认证密钥，作废 |
| 评论审核（在线） | 通过、隐藏、切换先审后发 |
| 账号设置 → 外观 | 毛玻璃模糊度（0–40px，按设备保存） |

改动先存在**这台设备**上（草稿态），网站上的其他人看不到。

## 怎么发布（v1 唯一方式）

1. 在手机的「数据管理」点 **导出内容包**，得到 `yacc-content-*.json`
2. 用这个文件替换项目里的 `public/content.json`
3. 提交并推送，托管平台自动重新部署（约 1 分钟）
4. 打开网站，内容就是新的了

> 这一步同时就是安全边界：只有能改仓库的人才能改变线上内容。
> 别人在自己手机上"当管理员"随便改，发布不了，影响不到网站。

## 怎么备份与换设备

- **导出完整备份**：包含内容 + 账号 + 收藏 + 历史，用于换手机。密码只存哈希，导出文件里没有明文。
- **导入**：会把整包覆盖到本机。导入前会先校验（格式、版本、引用完整性），校验不过就**什么都不改**。
- **撤销上一次导入**：导入会在覆盖前存一份快照，选错文件时能退回去。
- **清除本地草稿**：丢掉未发布的修改，回到线上版本。

导入是"先写待办标记、再正式落盘、最后清标记"的流程；中途被杀进程，下次打开会自动补完，不会留下半截数据。

## 已知限制（v1 有意如此）

1. **数据只在本机**。你改的东西别人看不到，必须导出发布。
2. **登录不是安全边界**。本地账号只用于区分"谁能看成员名单"的界面体验；真正的保护来自"能不能改仓库"。
3. **不自动抓取 B 站标题封面**。只解析视频 ID（跨域和风控会让自动抓取随机失效），标题和封面手动填。
4. **管理端排序用上下箭头**，不是拖拽（手机上更可靠）。

## 视觉说明

- 全局圆角：卡片 28、大面板 34、按钮 / 标签 / 输入框一律胶囊。
- 毛玻璃：导航栏、悬浮 Tab、卡片、输入框、弹层都用了 `backdrop-filter`，
  强度由 `--glass-blur` 控制，可在「账号设置 → 外观」里 0–40px 调节。

- 主页大标题会随滚动连续缩小（34px → 20px），到阈值时收进导航栏，
  导航栏同时从透明渐变为毛玻璃。
- 页面切换、卡片按压、弹层升起、Toast 都有过渡；系统开启「减弱动态效果」时自动降级。

## 常见问题

### 「浏览器不支持安全哈希」是怎么回事？

不是浏览器的问题。浏览器的 `crypto.subtle` **只在安全上下文可用**：

| 地址 | 安全上下文 | 能用 Web Crypto |
| --- | --- | --- |
| `https://…` | ✅ | ✅ |
| `http://localhost` / `http://127.0.0.1` | ✅ | ✅ |
| `http://192.168.x.x`（手机连局域网调试） | ❌ | ❌ |

用手机通过局域网 IP 打开时，浏览器会禁用 `crypto.subtle`，换 Safari / Chrome / 微信都一样。

现在已内置一个纯 JS 的 PBKDF2-HMAC-SHA256 兜底（和原生同算法，只是慢一点，约 80ms），
所以 **http 环境也能正常注册登录**，页面上会显示一行「已切换为兼容计算」。

账号记录里会写明用的哪种算法：

```
pbkdf2-sha256$100000$…      ← https / localhost 创建的
pbkdf2-sha256-js$20000$…    ← http 兼容模式创建的
```

两种都能登录；只有在「https 下创建、又用 http 打开」这一种情况下，会因为无法验证而提示你换回 https —— 这是数学限制，不是 bug。

部署到 https 后会自动走原生实现，无需任何操作。

## 账号编号规则（五位）

| 编号 | 含义 |
| --- | --- |
| `0xxxx` | 普通访客，后四位按注册顺序 |
| `1abcc` | 剧组成员：a=身份（1 导演 / 2 编剧 / 3 剪辑 / 4 摄影 / 5 演员），b=季（1/2/9=两季都参与），cc=顺序 |
| `2abcc` | 认证成员：a=年级，b=班级，cc=顺序 |

例：`12201` = 剧组成员、编剧、第二季、第 1 个；
`28710` = 认证成员、8 年级 7 班、第 10 个。

编号注册后不再变化（昵称可以改）。管理员生成密钥时选择编号规格。
